# UIX 覆蓋率報告

- 作者：PeterChang
- 最後修改：2026-10-12 01:32

顏色說明：<span style="color:#1a7f37"><b>綠色</b></span>是好消息或已完成，<span style="color:#cf222e"><b>紅色</b></span>是問題或風險，<span style="color:#0969da"><b>藍色</b></span>是關鍵數字或決定。

## 結論

在 602 個真實網頁上試用，UIX 大約有九成的情況能把風格完整套上去，而且幾乎不會把網站弄壞。

## 重點

- <span style="color:#0969da"><b>風格完整套上去的比例：90.0%</b></span>（就算把量不到的網站全部當成失敗，也還有 81.6%）
- <span style="color:#1a7f37"><b>網站被弄壞的比例：43 張截圖裡只有 1 張</b></span>，而且這個問題已經修好
- <span style="color:#1a7f37"><b>套用後字更好讀了</b></span>：原網站有 85% 的文字顏色夠清楚，套用後變成 99%
- <span style="color:#1a7f37"><b>大網站、小網站、台灣網站表現差不多</b></span>，沒有「只在大網站好用」的問題
- <span style="color:#cf222e"><b>換字型會讓版面移動</b></span>：平均三成的元素位置會跑掉，所以之後把換字型改成可選
- <span style="color:#cf222e"><b>我原本的自動檢查量錯了東西</b></span>：它只能看出「風格有沒有套上去」，看不出「網站有沒有壞」，所以改成兩種檢查分開看

## 我量了什麼

我想知道兩件事：

1. <span style="color:#0969da"><b>風格有沒有套上去</b></span>：用程式自動檢查。打開網頁、切換風格，看畫面上的文字有沒有變成風格的顏色、看不看得清楚。一個網頁在某個風格下，九成五以上的文字都過關才算成功。
2. <span style="color:#0969da"><b>網站有沒有被弄壞</b></span>：用人眼看。把套用前後的截圖放在一起，我一張一張判斷。

這兩件事聽起來很像，但量出來完全不一樣，後面「人工檢查」那段會講。

## 量了哪些網站

我從全球網站排行榜（Tranco）裡挑了三組，每個網站看首頁加一個內頁：

| 組別 | 怎麼挑 | 量到的網頁數 |
|---|---|---|
| 大網站 | 排行榜從第一名往下 | 235 |
| 一般網站 | 第 1 萬到第 100 萬名隨機抽 | 195 |
| 台灣網站 | 所有 `.tw` 網站隨機抽 | 172 |

排行榜裡很多其實不是網站（例如只是 CDN 或 DNS 伺服器），這些我都另外分類排除。真的網站卻打不開的，我會再試一次；最後還是打不開的有 31 個，主要是網站擋掉了自動化程式。

## 結果

| 組別 | 預設模式 | 強化模式 |
|---|---|---|
| 大網站 | 89.0% | 91.1% |
| 一般網站 | 90.4% | 91.9% |
| 台灣網站 | 90.8% | 93.1% |
| 全部 | <span style="color:#0969da"><b>90.0%</b></span> | 91.9% |

- 三組的數字差距都在誤差範圍內，可以當作一樣好。
- 10 種風格之間也差不多，最低的是 Dark（88.5%），最高的是自訂主色（90.9%）。
- <span style="color:#0969da"><b>最壞情況 81.6%</b></span>：把那 31 個打不開的網站，首頁和內頁都當成失敗重算。這是「再差也不會低於這個數字」。
- 擴充功能本身在 602 頁、每頁切換 20 次的過程中，<span style="color:#1a7f37"><b>一次錯誤都沒有</b></span>。
- 用 WordPress 做的網站稍微低一點（87.3%），但也還在誤差範圍內。

## 人工檢查

我抽了 22 個網站、44 張截圖，在不知道自動檢查結果的情況下自己看，判斷網站有沒有被弄壞（內容被蓋住、字看不清楚、版面亂掉、按鈕或圖不見都算壞，只是不好看不算）。

- <span style="color:#1a7f37"><b>只有 1 張壞掉</b></span>：一個台灣玩具網站，藍色導覽列被清成透明以後，上面的白色圖示看不見了
- <span style="color:#cf222e"><b>自動檢查和我的判斷幾乎對不上</b></span>：它說有問題的 5 張，我看都沒壞；它說沒問題的那 1 張，反而是真的壞掉的

我一張一張看下去，原因有幾種：

- 背景是整張圖片時，程式算不出字清不清楚，就直接當成失敗。這是程式的錯，已經修好。
- 自動檢查看了三個螢幕高度，截圖卻只拍了第一個螢幕，有問題的地方我在截圖上看不到。這是我設計的疏失，之後截圖改成拍三個螢幕高度。
- 有些按鈕文字留著網站原本的顏色，但看得很清楚。這是「沒套上去」，不是「壞掉」。
- 自動檢查只看文字，<span style="color:#cf222e"><b>看不到圖示</b></span>，所以那個白色圖示消失的問題它完全沒發現。

結論是：自動檢查適合用來看「風格套得完不完整」，但要知道「有沒有壞」，還是得靠人看。

## 量測過程中修掉的問題

量測工具本身也有 bug，而且這些 bug 都會讓結果看起來比實際好：

- <span style="color:#cf222e"><b>被當成機器人擋掉</b></span>：量測用的瀏覽器會自報是「無頭瀏覽器」，Adobe、OpenAI、IMDb 這些大網站直接拒絕連線。被擋掉的往往是設計最複雜的網站，排除它們等於只挑簡單的考。改成跟一般 Chrome 一樣的身分後重新量。
- <span style="color:#cf222e"><b>只有 www 能連的網站被誤判</b></span>：很多台灣網站只能用 `www.` 開頭的網址打開。程式先試沒有 `www.` 的網址失敗後，會干擾下一次連線，整個網站就被當成打不開。我一開始猜錯原因，修了一次沒效才找到真的原因。
- 其他還有：程式沒有時間上限導致卡住 17 分鐘、自動排程等錯了程序。

<span style="color:#1a7f37"><b>這兩個問題修掉後，總共多救回 94 個網站</b></span>，上面的數字都已經包含它們。

## 量完以後做的修正

上面的數字是修正前那一版量出來的。量完以後我改了這些：

- <span style="color:#1a7f37"><b>白色圖示消失：已修好</b></span>。原本是深色或彩色的導覽列，現在會換成風格的品牌色，不再清成透明，上面的白色圖示就看得到。用那個壞掉的玩具網站重測過。
- <span style="color:#1a7f37"><b>換字型改成可選</b></span>：預設只換顏色，版面就不會動；想換字型再自己打開，強化模式則會一起換。
- 網站裡用 Shadow DOM 做的元件（一種把樣式包起來的寫法），現在也會套到顏色。
- 新增 Alt+Shift+U 快捷鍵，游標在內嵌框架（iframe）裡也能叫出面板。
- <span style="color:#1a7f37"><b>網站的強制顏色現在也蓋得過去</b></span>（見下一段）。

## 為什麼有些字的顏色換不掉

大約 8% 的網頁，有超過 5% 的文字沒換成風格的顏色。我抽了 20 個這樣的網頁，一個一個查是哪一條設定決定了那些字的顏色：

- <span style="color:#0969da"><b>12 個還有沒換掉的字，其中 10 個（83%）是網站自己用了「強制」寫法（`!important`）</b></span>，而且寫得比 UIX 更具體，所以 UIX 蓋不過去
- 另外 8 個重測時已經沒問題了，應該是導覽列品牌色的修正順便解決的

事先我定的規則是：超過六成是這個原因，就改用瀏覽器的「使用者樣式」來注入 UIX 的設定。依照瀏覽器的規則，使用者樣式的強制寫法一定贏過網站的強制寫法。

- <span style="color:#1a7f37"><b>改完以後重測 4 個原本有問題的網站，文字全部換成功</b></span>：其中 3 個原本 10 種風格只過 0 到 1 種，現在 10 種全過
- <span style="color:#cf222e"><b>代價是安裝時的權限提示變多</b></span>：多了「讀取和變更你在所有網站上的資料」。不過 UIX 本來就會在所有網站上執行，實際能碰到的範圍沒有變大，變的只是提示文字

一個插曲：第一次分析的結果是「只有 42% 是強制寫法」，照規則會決定不做。我覺得「沒被 UIX 選到」的比例高得不合理，回頭檢查才發現分析程式有 bug，只查了第一層就停了。修好後才是 83%。如果直接用第一次的數字，就會做出相反的決定。

修正後新的檢查又發現一個問題：

- <span style="color:#cf222e"><b>深色風格下，深色的圖示會看不見</b></span>。網站把圖示顏色寫死成深色，背景一變黑就消失了。同一個玩具網站在 Dark 風格下只剩 45% 的圖示看得見，原網站是 87%。這個還沒修。

## 還不知道的事

- 只量了首頁和一個內頁，都是沒登入的狀態。
- 人工檢查只有我一個人看，樣本也不大（壞掉的只有 1 張），之後要找第二個人一起看，並刻意多挑容易壞的網站。
- 圖片做成的圖示，程式沒辦法判斷看不看得見，只能靠人看。

## 附錄：方法細節

給想追問的人：

- 抽樣用固定的亂數種子（20261011），名單在 `bench/strata/`，任何人都能抽出一樣的網站。
- 「九成」的信賴區間：87.6% 到 92.1%（以網頁為單位重抽 2,000 次）。同一頁的 20 次切換結果彼此相關，所以不把它們當成 20 筆獨立資料。
- 門檻敏感度：成功門檻設 90% 時是 94.4%，95% 時是 90.0%，98% 時是 82.4%。
- 「字看不看得清楚」用的是 WCAG AA 對比度標準（4.5 : 1）；圖示用 3 : 1。
- 人工檢查和自動檢查的一致程度：Cohen's κ = −0.04，等於跟亂猜差不多。
- 換字型造成的移動：預設模式 33.3%、強化模式 56.9% 的元素移動超過 4px；網頁自己會動的部分只有 2.3%，已經扣掉。
- 排除分類（大網站 / 一般 / 台灣）：
  - 試過 277 / 169 / 133 個網域，量到 140 / 113 / 95 個網站
  - 不存在 95 / 23 / 22，不是網頁 1 / 1 / 0，內容太少 33 / 15 / 10，擋自動化 8 / 15 / 4，打開失敗 0 / 2 / 2

重現指令：

```sh
npm install
npx playwright install chromium
node bench/sample.js --tranco <top-1m.csv> --out bench/strata
node bench/coverage.js --list <top-1m.csv> --sites 100 --workers 4 --out bench/results
bash bench/run-all.sh      # 人工檢查截圖、大網站內頁、一般網站、台灣網站
bash bench/retry.sh        # 分類排除的網站並重試
node bench/funnel.js       # 重新分類
node bench/report.js       # 產生 bench/results/report.json
node bench/audit-server.js # 人工檢查介面 http://127.0.0.1:8787
```
